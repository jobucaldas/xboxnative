  GlobalAddAtomW atom table directly (this mirrors real Windows/Wine, which

### What changed (core.cpp, new in this batch)
- GetDC/ReleaseDC: opaque per-call HDC handles tracked per-HWND (refcounted
  open/close bookkeeping only); no real GDI surface backs them (no rendering
  in this module, consistent with the "no fabricated success" bar used for
  ValidateRect/UpdateWindow in batch 2).
- LoadCursorA/LoadIconA/LoadIconW/LoadImageA/LoadImageW: ported Wine's actual
  call chain (LoadCursorA/LoadIconA/W literally call LoadImageA/W with
  LR_SHARED|LR_DEFAULTSIZE in dlls/user32/cursoricon.c) rather than
  reimplementing each separately. Only the standard-shared case resolves
  (hInstance==NULL, integer resource ID -> cached singleton handle, separate
  maps for icons vs cursors since IDC_ARROW and IDI_APPLICATION are the same
  numeric ID 32512 but distinct handle spaces). Module-resource loads
  (hInstance!=0), LR_LOADFROMFILE, and IMAGE_BITMAP honestly fail
  (ERROR_RESOURCE_DATA_NOT_FOUND / ERROR_FILE_NOT_FOUND / ERROR_NOT_SUPPORTED)
  because this module has no PE resource-section parser, file/codec decoder,
  or GDI bitmap backend — same honesty bar as SystemParametersInfoW's
  per-action ERROR_NOT_SUPPORTED in batch 2.
- DestroyIcon/DestroyCursor: one shared icon/cursor handle table (same as
  real Wine/Windows — DestroyCursor is not a distinct code path). Shared
  (system) handles no-op TRUE forever; handles this module actually
  allocated (via CreateIconFromResourceEx) are freed for real, and a second
  DestroyIcon on them correctly fails with ERROR_INVALID_CURSOR_HANDLE.
- GetIconInfo: correct fIcon/xHotspot/yHotspot for handles this module
  created; hbmMask/hbmColor are always NULL (documented: no GDI bitmap
  backend exists here at all, so these can never be real bitmaps — not
  claimed as a lesser bitmap, just absent).
- CreateIconFromResourceEx: real input validation ported from Wine (rejects
  dwVersion==0x00020000 and RIFF/.ani data, same as
  dlls/user32/cursoricon.c's CreateIconFromResourceEx), derives cx/cy from
  the caller's width/height or the embedded BITMAPINFOHEADER (halving
  biHeight for icons, since icon DIBs stack XOR+AND masks — same as Wine),
  then allocates a handle. No real bitmap is created (no GDI backend).
- LookupIconIdFromDirectoryEx: a genuine port of Wine's
  CURSORICON_FindBestIcon/CURSORICON_FindBestCursor best-fit search over
  caller-supplied CURSORICONDIR bytes. This is pure computation with no
  backend dependency (the directory bytes are caller-owned memory, not an OS
  resource), so it is implemented for real rather than stubbed — tested
  against synthetic 2-entry icon and cursor directories in test.cpp,
  confirming the near/far-size tie-break picks the documented entry.
- core.def: +12 exports. probe.h/check-play.py: missing-import gate tightened
  <=27 -> <=15 (tightening only; verified 121 total, 15 missing by scanning
  megabonk-user32.h against core.def's export names).
